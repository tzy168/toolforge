# ToolForge：一个会给自己造工具的 Agent

我想聊聊最近写的一个项目，顺便问几个我自己没想明白的问题。

先说怎么跑：`pnpm install && pnpm shared:deps && pnpm start`。或者在对话框里说「帮我看看这个 Markdown 里出现过哪些外链域名」。

仓库 github.com/tzy168/toolforge，Apache-2.0，版本 0.1.0。

![ToolForge 桌面端](../preview.png)

## 起因

随便打开一个 Agent 项目的工具目录，翻两个文件就能看到那个形状：一个 switch，按工具名分下去，每个 case 底下几十行。要加第八个工具，得写一个函数、在 switch 里加一个 case、在 system prompt 里补一段说明、再拼一份 JSON schema。

四件事，缺一件模型就用不上这个能力。而这四件事里没有任何一处需要你重新想一想这个系统。

我的问题一直是「还要支持什么」，从来没问过「一件工具到底长什么样，模型才用得对」。

## 它怎么工作

ToolForge 只有一个循环。模型拿到召回的工具，决定调哪个，结果回灌，继续。没有 tool_calls 就结束。

区别在于 `create_tool` 本身就是一件工具，不是循环之外的另一条流水线。模型发现手头没有能用的东西，就写一份规格出来，经过校验、静态扫描、跑它自己带的用例、按能力定级，入库，然后在同一个任务的下一步直接调用它。

我最早想给「造工具」单独做一条路径，写了半天发现那样等于承认核心循环处理不了自己的扩展。现在这条路上没有任何分支判断它是「新模式」。

有个细节是后来被缓存逼出来的：本轮的工具集一轮只算一次。

原来我每步都重新召回，觉得这样最灵活。结果模型服务的缓存命中率几乎是零。查了挺久才反应过来，那条缓存是从第 0 个 token 开始的逐字节前缀，tools 数组就在前缀里；而我的召回打分里有一项是「最近跑成功过的工具加 0.5 分」，工具一跑完就写 lastRun，下一步打分变了，顺序变了，整个前缀全废。一步几十 token 全量 miss，白 prefill 一遍。

现在只在工具清单真变了的时候重算，而且输出按工具名排序。选哪几件由分数决定，怎么排不该由它决定。

## 主要工作量在拦它，不在让它跑

能调工具的循环半天就写完了。剩下几天基本都在处理「什么东西可以进来」。

一件工具入库前要过：规格校验（没描述、没用例、参数边界含糊的直接打回）、依赖闸门、跑自带用例、按能力定级、状态流转。调用的时候再过一道统一闸门，可用性检查、Ajv 参数校验、权限判定、写审计。

| 等级 | 能力 | 默认 |
| --- | --- | --- |
| L0 | 纯计算 | 用例过了自动放行 |
| L1 | 只读网络或沙箱内跑代码 | 用例过了自动放行 |
| L2 | 写文件、读环境变量 | 转人工 |
| L3 | 执行外部命令、白名单外依赖 | 转人工或直接阻断 |

有三个地方改起来比功能本身费劲。

第一个是 status 和 trust 必须分开。status 管它现在能不能被调，trust 管它该不该问人，sessionId 管它是不是只在造它的那次会话里有效。我一开始合并过，合并之后「新建的工具到底能不能用」这句话就有了两种解释，而两种解释最后一定会在某个凌晨变成 bug。

第二个是报错得写给模型看。`spec.ts` 里那些 throw 现在都很啰嗦，比如「examples 不可为空：至少给一条 {args, expect}，无断言用例的工具不许入库」。它不会出现在日志里被人 review，它会原样进下一轮对话，模型看到就能改对。我一开始写的是 `invalid examples`，然后看着模型连续三轮改错地方。

第三个是先跑再问是不行的。白名单外的三方依赖，联网开关关着的时候我不光不装，连用例都不跑，因为跑用例就是执行代码。这条我犹豫过，它让「这个工具能不能用」在入库前完全无法判断，但它总比先斩后奏强。

## 踩过的坑

这部分没什么设计含量，但比上面那些更能说明它现在是什么状态。

`marked@18` 是 ESM-only。开发机上一切正常，Node 22 能 require ESM。打包到 Electron 里就不行了，它内置的 Node 是 20.18，直接 `ERR_REQUIRE_ESM`。`uuid@14`、`nanoid@6`、`he@2` 同理。所以离线依赖白名单里用的是仍提供 CJS 的老主版本，其中 `uuid` 最后被我整个删了，因为 ≤9 的版本已经废弃。

Windows 上 PowerShell 存文件默认带 BOM，`JSON.parse` 见到就抛，上层会当成「配置文件损坏」。现在读配置一律过一层 `readJsonFile`，它剥 BOM。同类的还有 `npx`、`npm`、`pnpm` 在 Windows 上都是 `.cmd`，起子进程不经 `cmd /c` 转一手就是找不到。

界面里那段流式渲染，最开始每来一个 delta 就重新解析一遍 Markdown。日志里看着没事，实际是 O(n²)，跑十几步之后明显卡，现在是按帧合并。

还有一个我改了很多次的：「切走任务再切回来，上下文不能丢」。写了二十多项自动检查之后才算稳定，之前每次出问题都是同一个原因，某个事件比 `chat()` 的返回值晚一拍到，被 `if (!liveRun) return` 整批丢掉。表现是过程块里少了最后一步的思考，时好时坏。

## 还没做好的

召回很粗。现在是名称、标签、描述的分词打分，中文按两字切。工具到几十件的时候它就开始挑错，只是错得不明显，所以还没出事。往向量走会破坏缓存前缀的稳定性，我还没想好怎么同时要这两样。

没有评测。我有 22 条单元测试和十几项端到端自检，但它们证的是「代码没坏」，不是「这个版本比上个版本更会干活」。这件事挺要命，因为没有评测的话，改提示词基本等于凭感觉调参，而我确实一直在凭感觉调。

隔离是打折的。静态扫描是正则启发式，`node:vm` 本来就不该被当成安全边界，Electron 内置 Node 缺 `--permission` 的时候会降级成没有 OS 级隔离。界面上会显示 `probed: false`，但用户不会去看设置页。

成本也没有建模。一个任务跑二十步，每步都带工具 schema。现在只有步数上限和结果截断两道粗闸，没有按预算调度的能力。

## 想问的

- 工具协议该自己做还是直接贴 MCP？现在这个形状能统一做定级和审计，代价是吃不进生态。有没有人试过两边都要，实际维护成本是多少？
- 缓存前缀稳定性和向量召回真的能同时要吗，还是我该放弃其中一个？
- 小项目的评测从哪开始比较务实？我知道该有回归集，但「五十个任务」从哪来、怎么判定成功、失败之后怎么归因到具体那次改动，我不想为了做评测先去做一个标注平台。
- 沙箱降级这件事，除了在设置页写一行字，还有别的做法吗？
- 工具该不该改自己？现在一个工具错了就删掉重建一个新的，旧版本存在 `.history/` 里但没人看。什么时候该让它去改上一次写的东西，什么时候不该，我完全没想清楚。

---

要试的话，`pnpm cli` 是终端 REPL，不用起 Electron。`doc/` 下有八篇源码笔记，从一次调用怎么穿过整个系统，讲到怎么加一种新的工具类型。

如果只做一件事，我建议让它给你造一件自己的工具。整个过程里唯一让我觉得这个东西成立的地方，是它造完、我确认了一遍规格、它下一步就直接用上了，而我没写一行代码。其余时间我都在跟它吵架。
